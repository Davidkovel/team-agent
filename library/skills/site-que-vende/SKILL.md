# Site que vende

Bonito não chega. Cada bloco responde a uma pergunta que o cliente faz naquele momento. Se não responde, sai.

## 1. Perguntas (antes de qualquer pixel)
1. **Quem compra?** Separar segmentos (ex.: empresas vs particulares) e dar a cada um o seu botão logo no hero.
2. **Que dor?** 2–3 situações concretas nas palavras do cliente (o que perde: dinheiro, tempo, nervos).
3. **Como resolvemos?** Benefício, não funcionalidade.
4. **Porquê nós?** Um facto verificável + uma garantia. "Qualidade e rapidez" não conta.
5. **Como comprar?** Um passo principal e o que acontece depois dele.

## 2. Concorrentes (1–3, todas as páginas)
Ler home, serviços, uma página de serviço, casos/projetos, sobre, blog, contactos (`ctx_fetch_and_index` por página; `curl` cru só devolve scripts em WordPress). Anotar:
- o que prometem e onde soam todos iguais (aí está o nosso lugar);
- provas: casos com números? avaliações com nome? certificados explicados ou só ícones?
- contradições (anos, nº de línguas, horário) — são ouro para nós;
- como se compra: calculadora, prazo de resposta, canais.

## 3. Estrutura da home
Hero (resultado + para quem + garantia + 2 botões) → logos → **dor** ("Isto é familiar?") → o que fazemos → **casos com número + citação** → **tabela "nós vs freelancer vs agência típica"** → como começar em 3 passos + formulário → FAQ com objeções ("e se rejeitarem?", "porque não um freelancer mais barato?") → CTA final.

## 4. Regras
- Mesmos números em todo o site.
- Casos e avaliações só reais; números inventados ficam marcados como exemplo e nunca vão para produção.
- Garantia só se o dono a aceitar.
- Mostrar primeiro em maquete (cópia do site + screenshots antes/depois), depois aplicar no site com backup.

Exemplo feito: Lingvo/Glossa (C:\Users\David\glossa) vs mk-translations.ua, 29.10.2026.
